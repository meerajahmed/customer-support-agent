Design decision: I implemented the loyalty discount as a tool that runs a Python code string in the AgentCore code interpreter instead of letting the model do the arithmetic. The rules (100 points = $1, redemptions in blocks of 500, capped at 50% of the order, plus a tier discount) must be exact and repeatable, and language models are unreliable at multi-step maths. In Test 5, a Gold member with 4250 points on a $150 order got 4,000 points redeemed, an $11 tier discount and a $99 final total, which matched my hand calculation. I also added a fallback that applies only the tier discount if the sandbox is unavailable, so the agent degrades gracefully instead of failing.

Challenge: Long-term memory failed on my first run: in Test 4, new session did not remember Jane's name or her preference for concise answers. The problem was hard to see because my MemoryHook wrapped everything in try/except and logged nothing on success. I added logging for the namespaces found, records retrieved and events saved, made namespace handling tolerate unknown placeholders, and read the CloudWatch logs. I also learned to run agentcore stop-session after redeploying, because the CLI reuses a warm session that can keep running old code. After waiting three minutes between sessions, the agent recalled both facts.

Production: My sandbox gateway uses the NONE authorizer, which would be unacceptable in production. I would use OAuth/JWT based authentication like Cognito service or IAM authorization, take the customer ID from the verified token instead if the request payload, and give each tool a least-privilege role. I would also cap refund amounts and require human approval above a threshold, add guardrails against prompt injection from browsed web pages, and set CloudWatch alarms on tool errors and latency, along with budgets for model and browser costs.
